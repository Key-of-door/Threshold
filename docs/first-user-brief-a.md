# 用户任务 A：第一次使用 Threshold

> 操作者交付前，仅在此填入实际安装入口、面向用户的 README 位置、练习 Git 目录，以及可用 provider/model 和公开配置位置。此提示块填妥后替换为环境事实；不提供操作步骤或内部资料。

请作为第一次接触 Threshold 的用户，只依据用户 README 和 CLI 帮助安装并使用它。
不要读取 Threshold 的实现源码、历史报告、内部数据库或通过内部 API 操作；不要修改 Threshold 本身。
如果必须依赖这些材料或作者解释才能继续，请记下阻断位置，不要自行修产品绕过。

在给定的练习仓库，用 Threshold 管理并交给 Pi worker 完成这个小项目：

**log-summary**：零依赖 Node 工具，读取 UTF-8 NDJSON 日志。每个非空行是一条 JSON 对象，level 必须是 info、warn 或 error；统计并返回这三种级别的数量，缺失的级别计 0。
空行忽略。坏 JSON、缺失/不支持 level 必须报告输入文件中的行号。
最终还需要一个接受输入文件路径的 CLI：成功向 stdout 输出统计 JSON；失败向 stderr 输出清楚错误并非零退出。需要对应测试和简短使用说明。

请建立或找到当前 Project，建立包含完整需求的 Task。
这次先让 worker 完成解析/汇总模块与相关测试，CLI 留给后续工作。通过产品保存停点，查看结果与状态，然后正常停止服务，结束本次会话。
不要自己代替 worker 完成代码；可以查看练习项目和运行检查。

README 读多少、何时转去看 help，由你按正常使用习惯决定。
记录真实使用摩擦：第一反应尝试的命令、输出哪里不清楚、哪些信息需要猜、哪里需要作者帮助。若你实际准备通过调查 Threshold 内部来继续，请公开说明遇到了什么用户入口缺口，然后保持上述黑盒边界；不要求提供隐藏推理。无需强行寻找问题，也不必写长报告。
不要提交或推送任何远端变更，不读取/打印密钥。模型配置已作为环境提供；若实际不可用，报告准确技术错误。
