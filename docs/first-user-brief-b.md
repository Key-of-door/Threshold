# 用户任务 B：回来继续一个项目

> 操作者交付前，仅在此填入同一版本的用户 README 位置、练习仓库的子目录，以及正常可用的运行环境事实。不要填入 A 的结论、Task/Run ID、checkpoint 或操作解法。

你现在要用 Threshold 继续这个练习项目已有的未完成工作。你没有上一位使用者的对话。
请从用户 README、CLI 帮助、产品中保存的项目状态，以及实际 Git/files 重新了解现状，找到项目和任务，让新的 Pi worker 继续完成。

不要读取 Threshold 实现源码、历史实验、内部数据库，或通过内部 API 绕过 CLI；不要修改 Threshold 本身。
不要自己代替 Pi worker 编写未完成的功能；你可以查看练习项目并运行检查。
如果用户入口不足以继续，记录具体阻断，不要通过调查内部实现或请求作者搬运背景来悄悄补齐。

查看状态，核对实际交付与测试，并通过正常产品接口留下最终状态。完成后正常停止服务。
README 读多少、何时转去看 help，由你按正常使用习惯决定。
记录任何猜测、重复输入、信息缺失或求助，也允许结论是使用顺畅。若实际准备调查 Threshold 内部，请公开说明缺少什么用户信息，但不要突破黑盒边界，也不要求提供隐藏推理。不要将上一个 Agent 的摘要自动当作事实。

不要提交或推送任何远端变更，不读取/打印密钥。若配置或服务发生技术问题，请报告实际错误与尝试过的用户操作。
